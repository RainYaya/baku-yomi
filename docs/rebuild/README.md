# baku-yomi 从 0 到 1 复刻手册

> 目的：不是读文档，而是**跟着指南亲手把整个项目从空目录敲出来**。30 课课程是原理参考书，这里是你从 0 到 1 的施工图纸。
> 使用方法：每个里程碑 = 一段完整施工流程，**按 Step 顺序一步步做**——每步有要写的代码、逐行讲解、验证方法。做完一个里程碑再进下一个。

## 为什么这样学

- 这套指南把每个里程碑拆成**按序执行的施工步骤**，每步都是「可运行的中间状态」：做完一步项目就能跑，跑通再做下一步。这就是真实开发的方式——小步前进，随时可验证。
- 复刻顺序参考了真实提交历史的功能演进（EPUB 解析 → 阅读 → 状态 → AI → 练习 → 键盘 → 书签 → TTS → 书架 → 主题 → 部署），这是**合理的开发顺序**，但实现一律对照最终成品，不照抄历史中间态。
- 每个里程碑结束都有「与最终代码的差异复盘」，列出**后续里程碑会长出来的部分**——你看代码时的所有疑惑（为什么这里有这个？）都能在这张清单里找到答案。
- 历史里的弯路（被删的功能、被推翻的设计）以「设计注记」形式收尾——**讲结论，不重建现场**。

## 施工方法（每个里程碑）

1. **看构筑总览**：先知道这个里程碑要长出哪些文件、最终长什么样
2. **按 Step 顺序施工**：每步 = 做什么 + 完整代码 + 逐行讲解 + 验证动作。**先别看代码自己试，卡住再对照**——讲解部分是答案，也是理解
3. **每步验证**：指南里标注的验证动作（curl / 浏览器操作 / build）必须亲手跑一遍
4. **收尾验收清单**：全部勾选才算完成本里程碑
5. **读差异复盘与设计注记**：想清楚「最终版比我多了什么、为什么」

## 施工节奏建议

- 每里程碑约 1-2 天；M1（解析管线）和 M8（TTS）是硬骨头，可以多给时间
- 每完成一个里程碑，**把代码跑起来用一遍**再进下一个——「能用的软件」比「写完的代码」重要
