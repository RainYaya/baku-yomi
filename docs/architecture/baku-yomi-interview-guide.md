## 二、图的结构（先让面试官 10 秒看懂）

图分 **三个信任区（region 边框）**，共 11 个核心组件：

- **左・ブラウザ（ユーザー端末）**：BYOK キーストア、Web クライアント、EPUB 取り込み、バイリンガル読書
- **中・baku-yomi サーバー（Hono, Node.js）**：API ゲートウェイ（标签「信頼境界」）、AI 採点サービス（标签「制限 30回/分」）、AI プロバイダ SDK、TTS サービス（标签「WAV キャッシュ」）
- **右・外部 / サードパーティ**：AI ベンダー API、Microsoft Edge TTS、VOICEVOX エンジン（标签「任意」）

**粗线（emphasis）= 主路径**；**红线（security）= 信任边界跨越**；**虚线 = 次要/可选路径**。

## 三、图解题_track（指哪说哪，节点名用日文）

### A. ブラウザ区（指：左侧 4 个节点）

> まず左の「ブラウザ（ユーザー端末）」の枠です。ここに 4 つあります。EPUB を取り込む「EPUB 取り込み」、文単位で日本語と中国語を並べて読む「バイリンガル読書」、そして React 19 で作った「Web クライアント」。**一番上の「BYOK キーストア」は、ユーザーが持ち込んだ AI の API キーをブラウザの localStorage にだけ保存する仕組みです。つまり鍵は端末から出ません。**

### B. 主路径（先点「逆訳メインパス」视图，再依次指：バイリンガル読書 → API ゲートウェイ → AI 採点サービス → AI プロバイダ SDK → AI ベンダー API）

> 中央の強調された線が主経路です。ユーザーが中国語から日本語へ逆訳（バックトランスレーション）を入力すると、「バイリンガル読書」から「API ゲートウェイ」へ HTTPS で送り、そこから「AI 採点サービス（/api/analyze）」へルーティング、さらに「AI プロバイダ SDK（Vercel AI SDK）」を通って「AI ベンダー API（OpenAI / Anthropic / Google）」を呼び出します。採点・添削結果は同じ経路を戻ります。

### C. 信任边界（指：BYOK キーストア → API ゲートウェイ 的红线；及网关上的「信頼境界」标签）

> ここがこの設計の肝です。「BYOK キーストア」から「API ゲートウェイ」へ向かう赤い線——API キーはリクエストごとにゲートウェイへ渡りますが、**自分のサーバーには一切保存しません**。ゲートウェイには「信頼境界」と書いてあり、本番では CORS を固定オリジンに制限しています。これがブラウザとサーバーの信頼境界です。

### D. 外部依赖（指：右侧 AI ベンダー API / Microsoft Edge TTS / VOICEVOX エンジン 及其连线）

> 右の「外部 / サードパーティ」の枠が外部依存です。AI は上の API、音声は「Microsoft Edge TTS」（無料・設定不要が既定）と、任意で「VOICEVOX エンジン」（Docker で別起動）の 2 種。TTS はサーバー側で WAV キャッシュ（既定 120MB）します。

### E. 补充卡片（依次指下方 3 张卡，或口头带过）

> 下の 3 枚のカードが補足です。**ブラウザの信頼境界**（鍵は localStorage のみ）、**サーバー側の境界**（/api/analyze を IP ごと毎分 30 回にレート制限、TTS は WAV キャッシュ）、**外部依存**（AI は Vercel AI SDK 経由、TTS は 2 方式）をまとめています。

## 四、想定質問 × 図を使った回答

| 質問 | 回答骨架（指图） |
|---|---|
| なぜサーバーを経由する？ブラウザから直接 LLM を呼ばないのか？ | BYOK なので直接呼び出しも可。だが **TTS プロキシ・レート制限・将来の認証/監査**のために「薄いゲートウェイ」を置いた。**トレードオフ（レイテンシ vs 統制）を意識**して選択。（指：API ゲートウェイ + TTS サービス） |
| セキュリティ上の懸念は？ | 鍵を localStorage に置くので **XSS リスクは正直にあり得る**。緩和策は CORS 固定＋レート制限。より安全な案は**短期トークン化・CSP 導入・バックエンド保管＋スコープ制限**。（指：BYOK キーストア → API ゲートウェイ 红线） |
| 採点の精度はどう担保している？ | LLM に構造化プロンプトで `【综合评分】` 形式の出力をさせ、フロントで正規表現で点数を抜き出し。**出力の揺らぎという限界は認識**しており、改善案は JSON モード／スキーマ検証。（指：AI 採点サービス → AI プロバイダ SDK） |
| なぜ Hono / Zustand / Vercel AI SDK？ | Hono は軽量で Node/エッジ両対応；Vercel AI SDK は OpenAI/Anthropic/Google を一 interface に統合でき BYOK の複数プロバイダ切替に向く；Zustand はボイラープレートが少なくリーダー状態管理に適する。（指：各ノード） |
| コストは？ | Edge TTS は無料・設定不要を既定、VOICEVOX は任意；TTS はサーバー側で WAV キャッシュ、/api/analyze は IP ごと毎分 30 回制限。（指：TTS サービス + 外部 TTS） |

## 五、弱点の先出し（指「外部」或「サーバー」区，主动说）

> 正直な反省として、**自動テストがまだ不十分**で、レート制限は**インメモリ（単一プロセス前提）**です。次は **Vitest** で核心ロジック（EPUB 文ペア解析、採点結果パース）からカバーし、スケールアウト時は **Redis 等へ移行**したいと考えています。

（主动说风险 = 成熟度。比被问「テスト書いてる？」后支吾强十倍。）
