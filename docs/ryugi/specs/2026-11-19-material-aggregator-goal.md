# baku-yomi · 材料聚合器 + 全局练习记录 · Goal

> 日期：2026-11-19
> 状态：许愿式 goal，可直接交给执行者一条龙跑完
> 前置：`docs/HANDOFF.md`、`docs/design/ui-v2-interaction.md`、`docs/ryugi/specs/2026-11-19-note-source-design.md`

## 1. 为什么做这个

现在 baku-yomi 的能力是完整的：EPUB / 粘贴 / URL 导入、双语阅读、回译练习、AI 讲解、TTS、生词本、练习回顾。问题不在“读不了”，而在三件事：

1. **材料要自己找**。每次都得先找文章、复制、导入，没有“打开就有日语材料”的地方。
2. **练过的句子散在各本书里**。现有 `ReviewPage` 其实已经是全局批改记录，但入口不显眼、没有来源标签、没有多次尝试历史，也没有“随机抽一句”。
3. **缺自己需要的材料**。想练“在日本买衣服”“和同事聊动漫”“IT 工程师日常”这类情景，只能等找到现成文章。

这一轮不追更多阅读器功能，而是把“材料 → 阅读 → 练习 → 记录 → 再练”补成一个循环。

---

## 2. 产品模型

- **Material（材料）**：一本书 / 一章 / 一对句子。所有材料都有 `source`。
- **Source（来源）**：产生材料的入口。现在有 EPUB、粘贴、URL、合集；本轮加 **note**、**AI 情景**、**字幕**。
- **Library（材料库）**：书架升级成材料库，按来源筛选、显示来源徽章、提供统一的“添加材料”入口。
- **Practice Journal（练习记录）**：全局的、跨材料的练习档案；记录每次批改、支持筛选、回到原句、再练。
- **Random Practice（随机练习）**：从材料库里随机抽句子练，可限定来源 / 没练过的 / 70 分以下。
- **AI Scenario（AI 情景材料）**：用户描述情景，AI 生成双语对话，保存成普通材料。

不是新做一个 app，也不是重写阅读器；是给现有结构加“来源”和“记录”两条边。

## 3. 目标（核心，必须做完）

### 3.1 材料库（M0）

- 书架页升级为材料库：
  - 来源筛选：`全部 / 书 / AI 情景 / 字幕 / 链接 / 合集`。
  - 每张书卡显示来源徽章：`EPUB`、`粘贴`、`链接`、`合集`、`AI 情景`、`字幕`。
  - 顶部有统一的 **「添加材料」** 菜单：导入 EPUB、粘贴 / URL、导入字幕、AI 生成情景、添加 note 来源。
  - note 作为“来源”单独一张卡（未读数、已打开篇数、打开 note 视图），不把每篇 note 文章平铺进书单。
- 首页升级为聚合仪表盘：
  - 继续阅读（含 note 材料，带 note 徽章）。
  - 添加材料入口。
  - 最近材料（带来源徽章）。
  - 练习记录卡片：累计批改、待复习（70 以下）、最近几条、「查看全部」「随机练一句」。
  - note 未读卡片（有 note 来源时才出现）。
- 新增 `src/lib/library/sources.ts`：
  - `sourceLabel(book)`、`sourceGroup(book)`、`isNoteBook(book)`、`visibleBooks(books)`。
  - 所有组件共用，不在每个页面各写一份 `filter`。

### 3.2 note 来源（M1）

完整实现 `docs/ryugi/specs/2026-11-19-note-source-design.md`：

- 独立 note 视图：话题/作者来源、RSS 列表、未读、屏蔽词、管理来源。
- 点文章才抓正文；存进 note 书；复用阅读器/翻译/生词/进度。
- 默认话题 `#エッセイ`、`#暮らし`、`#読書`、`#小説`；默认屏蔽政治/选举/战争/宗教/投资/新闻等。
- 只支持公开文章；付费/限定给明确提示，不偷偷存半篇。
- 详细的数据、路由、测试、验收都在 note 设计里，按它做。

### 3.3 全局练习记录（M2）

**不要新建第二个记录页**。现有 `ReviewPage` 已经是跨书的全局记录，把它升级：

- 可见标题改为「练习记录」（view id 仍是 `review`）。
- 数据：
  - 新增 `attempts: Record<pairId, PracticeAttempt[]>` 到 `practice-store`（v2 迁移）。
  - `PracticeAttempt { translation, analysis, at }`；每次 `setAnalysis` 追加，单句最多保留 10 次。
  - 旧 `analyses` 仍然是“最近一次”，保持兼容；迁移时用旧 `analyses` + `translations` 种入第一条历史。
- 列表：每句一条，显示原句、中文、最近回译、分数、练习次数、来源材料（书名 + 来源徽章）、最近日期。
- 展开：批注 + 该句的尝试历史（第 1 次、第 2 次…分数/回译/时间）。
- 筛选：材料、来源、分数段、错误类型、日期范围、搜索；排序最近/最低分。
- 顶部摘要：累计批改次数、去重句子数、材料数、70 分以下句数、本周练习数。
- 入口：首页练习卡片 + 书架/顶栏「练习记录」；不再只藏在顶栏。
- 全部来源都进记录：EPUB、粘贴、URL、合集、note、AI、字幕。
- 不做打卡、连续天数、SRS。

### 3.4 随机练习（M3）

- 首页和练习记录页都有 **「随机练一句」**。
- 抽题池 = 所有材料的所有句子；排除空句。
- 筛选（我的默认，执行者可微调）：
  - 全部材料 / 当前来源 / 当前材料；
  - 只抽没练过的（`analyses[pairId]` 不存在）；
  - 只抽 70 分以下；
  - 最近 20 次抽过的不重复。
- 点击后：`setCurrentBook` / `setCurrentChapter` / `setScrollToPairId` / `setPracticePairId`，进入阅读器并打开该句的练习界面。
- 批改完成后，练习卡里给一个 **「再抽一句」** 入口；不要求一次抽一整个队列。
- 如果池子为空，显示为什么空（例如“当前筛选下没有没练过的句子”）。
- 纯逻辑放 `src/lib/practice/random.ts`，有测试（池子、筛选、去重、空池）。
- 可选 stretch：一次抽 5 句的队列/进度条；如果实现成本明显变大，停在“一次一句 + 再抽一句”。

### 3.5 AI 情景材料（M4）

用户描述情景，AI 生成一份可直接读的双语材料。

- 入口：材料库「添加材料」→ **AI 生成情景**。
- 对话表单：
  - 情景描述（必填，2–500 字），例如“在日本买衣服时和店员对话”“和同事聊动漫”“IT 工程师日常站会”。
  - 水平：N5 / N4 / N3 / N2 / N1（默认 N3）。
  - 形式：对话 / 短文（默认对话）。
  - 长度：短（6–8 行）/ 中（10–14 行）/ 长（16–20 行），默认短。
- 生成：
  - 用当前激活的 AI 供应商（设置里的 provider/key/model）。
  - 新增 `server/routes/generate.ts` 的 `POST /api/generate-material`，带限流；或复用现有 `/api/analyze`，但必须有严格的 JSON 校验和一次重试。执行者选实现，行为必须一致。
  - 输出 JSON：`{ title, level, format, lines: [{ speaker?, japanese, chinese }], notes: [{ word, reading, meaning }] }`。
  - 要求自然口语、不要翻译腔、水平匹配、说话人清楚、中文翻译准确。
- 预览与编辑：
  - 显示标题、逐行日语/中文、3–5 个关键词（读音/释义）。
  - 标题和每行可编辑；可「重新生成」；解析失败显示可见错误并可重试。
- 保存：
  - 生成一本普通书，`source.kind = 'ai'`，`source.scenario` 存原始情景，标题用 AI 标题。
  - 一个 chapter，pairs 由行生成；保存后直接进阅读器。
  - 书卡带 `AI 情景` 徽章；阅读器/翻译/生词/练习全部照常。
- 不做：自动把关键词写进生词本（可以之后手动加）；不把 AI 输出当权威译文；不生成整本书。
- 测试：JSON 清理/校验、行→pair、空/坏输出、重试路径；至少用一个真实情景手动生成一次。

### 3.6 字幕导入（M5）

- 入口：材料库「添加材料」→ **导入字幕**；接受 `.srt` / `.vtt`。
- 解析：
  - SRT/VTT 的 cue：去掉序号、时间轴、`<i>/<b>`、ASS 样式标签 `{\an8}` 等。
  - 多行 cue 合并；保留说话人前缀（`- `、`A:` 等）。
  - 双语检测：日语行 + 中文行 → 直接配对；只有日语 → 中文留空，阅读器里可按章 AI 翻译。
- 保存：一个文件 = 一本书（一章或多章按空行/场景切分；MVP 一个文件一章即可），`source.kind = 'subtitle'`，标题用文件名（去扩展名）。
- 测试：SRT fixture、VTT fixture、双语配对、单语、脏格式、空文件。
- 不做：视频同步、字幕时间轴播放、批量目录导入。

### 3.7 URL / 天声人语 / 合集（M6，收尾）

- 现有 URL 抓取和“粘贴到目标书/合集”已经能用；本轮只做入口和可见性：
  - 「添加材料」里放“粘贴 / URL”；
  - 书卡显示 `链接` / `合集` 徽章；
  - 文档里写清“天声人语这类每日文章：建一个合集，每天把 URL/正文追加进去”。
- **不自动抓报纸/专栏**，不绕过付费墙，不内置受版权保护的正文。
- 不做通用 RSS 阅读器。

## 7. 分阶段（同一个 goal 内顺序执行）

| 阶段 | 内容 | 自检 |
|---|---|---|
| **M0** | 来源类型/徽章/筛选 helper；书架→材料库；首页聚合卡；添加材料菜单 | 类型/筛选纯函数测试；现有书架功能不回退 |

| **M2** | 练习记录升级：attempts v2、迁移、摘要、筛选、历史、首页入口 | 迁移测试、记录纯函数测试、旧数据可读 |
| **M3** | 随机练习：池子/筛选/去重/打开练习/再抽一句 | 纯函数测试 + 手动抽 5 次 |

## 8. 验收

### 功能

1. 材料库能按来源筛选；每张书卡有来源徽章；「添加材料」包含 EPUB、粘贴/URL、字幕、AI 情景、note。
2. note：默认话题有内容；能加/删来源；点文章才抓正文；能翻译、存生词、刷新后还在；屏蔽词生效。
3. 练习记录：全部来源的批改都在；摘要数字正确；筛选/搜索/排序正确；展开能看到多次尝试；旧数据迁移后仍显示。
4. 随机练习：能从全部/指定来源抽；没练过/70 分以下筛选正确；不连续重复；能打开对应句子并练习；空池有解释。
5. AI 情景：描述“在日本买衣服”能生成可读的双语对话；预览可编辑；保存后进材料库/阅读器；坏 JSON 有可见错误和重试。
6. 字幕：导入一个 SRT 和一个 VTT 能读；双语/单语都对；脏格式不崩。
7. URL/合集：把一篇 URL 追加到合集能读；书卡显示来源。
8. 现有功能：EPUB、粘贴、URL、讲解、TTS、书签、生词、主题、桌面双栏分页、手机选中都不回退。

### 工程

- `pnpm test` 全绿；`pnpm exec tsc -b`、`pnpm build` 通过。
- lint 不新增错误（当前基线本来就不绿：11 errors + 1 warning，见 HANDOFF；用改动前后的列表对比）。
- 新纯逻辑都有测试；组件保持薄。
- 旧 localStorage 数据（书、练习、生词、书签）迁移后可读；导出/恢复备份可用。
- 宽度检查：2022×954、1100×800、744×1134、390×844。
- 至少手动跑一遍核心链路：note 文章 → 练习 → 记录 → 随机再练；AI 情景 → 练习。

## 9. 执行规则（一条龙）

- 自主执行，不在 milestone 之间问人；遇到小决定自己拍板，在最终报告里列出“我的判断”。
- 先读代码再改；不凭记忆改。
- 纯逻辑先写失败测试再实现（TDD）；组件只做渲染和连接。
- 不新增大依赖；SRT/VTT 用小型解析器即可；RSS 解析优先自己写并配 fixture，除非 `fast-xml-parser` 明显更稳且体积可接受（要说明）。
- 保护现有数据：所有 persist 变更加 versioned migrate；迁移有测试；不做破坏性写入。
- 不 commit / push，除非用户明确要求。
- 最终报告：
  - 做了什么（按 M0–M6）；
  - 怎么验证的（命令输出/手动步骤）；
  - 我的判断（默认值、取舍）；
  - 没做的/已知问题；
  - 下一步建议。
- 如果某个 milestone 明显超出本 goal，停下来报告，不要静默扩 scope。
