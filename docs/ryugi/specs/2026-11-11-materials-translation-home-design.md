## 1. 背景与判断

baku-yomi 现在的核心是：双语阅读 → 选中句子 → 回译练习 → AI 反馈/讲解。

当前状态：

- 双语材料主要靠“沉浸式翻译”插件制作，再导入 EPUB；
- 材料基本是 EPUB 小说，来源单一；
- 书架是落地页，功能可用，但缺少“继续阅读”和“添加材料”的明确入口；
- 练习结果（`AnalysisResult`）已经持久化，但没有地方回看；
- 书籍、封面、练习数据都在 localStorage，接近配额时会静默失败。

这一轮的判断：

> 不是把 baku-yomi 做成内容平台，而是把“材料 → 双语 → 阅读 → 练习 → 复盘”这条核心循环补完整。

约束：

- 个人使用优先，已经公开但预期用户很少；
- 不做账号、共享额度、复杂后端；
- 阅读优先，不做强制刷题/打卡；
- 不需要为规模提前设计，但该修的数据问题要先修。

---

## 2. 已经确定的方向

1. **站内做双语**：值得做，而且应该做。按章翻译，用户触发，不自动翻整本。
2. **输入源**：不是 RSS/订阅，而是“添加材料的方式”。粘贴文本是通用入口，URL 抓取是锦上添花，合集是手动分组。
3. **首页**：把书架升级成“书桌首页”，书架保留为库；空状态做成真正的展示/引导页。
4. **不做每天都要经过的营销首页**：首页的主动作是“继续阅读”和“添加材料”。
5. **公开但不为规模过度设计**：不加账号、不做共享额度、不做社区。

## 3. 要做的

### P0-1. pair ID 全局唯一 + 数据迁移

**现状（代码事实）**

- `src/lib/epub/pairBuilder.ts` 和 `src/lib/epub/immersiveTranslate.ts` 生成的 id 是 `ch{chapterIndex}-p{pairIndex}`，不带 bookId。
- `src/stores/bookSlice.ts` 的 `updatePairChinese(pairId, chinese)` 会遍历所有书，更新所有同 id 的句子。
- `src/stores/practiceSlice.ts` 的 `translations` / `analyses` / `notes` 也只按 pairId 存。

**后果**

- 两本书都有第 1 章第 1 句时，在 A 书改译文会同时改到 B 书。
- 两本书的练习记录会串。
- 单本书时看不出来，多本书就是静默数据错误。

**修法**

- pair id 改成 book-scoped，例如 `{bookId}-ch{chapterIndex}-p{pairIndex}`，或直接用 `chapterId + pairIndex`。
- 在 persist 的 `migrate` 里重写旧书数据。
- 同时迁移 practice / bookmark 里以 pairId 为 key 的数据。
- 加测试：两本书同章节/同句序号，编辑和练习互不影响。

**验收**

- 两本书可以独立编辑译文、独立练习、独立复盘。
- 刷新后迁移结果保留。
- 旧数据不丢。

---

### P0-2. 存储配额提示 + JSON 导出/导入

**现状**

- `src/lib/debouncedStorage.ts` 在 `localStorage.setItem` 失败时直接 catch，不提示。
- 书籍包含全文和封面 data URL；翻译会让文本量接近翻倍。
- localStorage 通常只有约 5MB。

**要做**

- 估算当前 book-store / practice-store / bookmark-store 的体积。
- 接近阈值（建议 3.5–4MB）时显示可见提示。
- 写入失败时不要静默：给出明确错误，并提示导出备份。
- 提供 JSON 导出/导入：书籍、练习、书签、设置至少覆盖书籍和练习。
- IndexedDB 先不迁；当出现一次配额失败，或体积长期接近 4MB 时再迁。把触发条件写进文档。

**验收**

- 配额提示可见。
- 导出后能在空环境导入恢复。
- 写入失败不会无声丢数据。

---

### P1-1. 站内按章翻译

**范围**

- 按章/按文章翻译，用户点击才执行；不做整本自动翻译。
- 单语章节正常读，中文为空时不显示译文。
- 翻译完成后中文出现在句子下方，和现有双语阅读一致。

**流程**

- 章节头/尾提供“AI 翻译本章”入口。
- 约 20 句一批，带上下文请求。
- 要求返回同数量的 JSON（带 id）；数量不匹配时重试一次，再降级逐句。
- 进度可见、可取消、失败可重试。
- 每批完成就写入 store，不整章攒到最后。
- 已翻译的句子不重复翻译；重新翻译需显式触发。

**质量与校对**

- 译文标记为“AI 译文”。
- 每句可编辑（复用现有 `updatePairChinese` 和“编辑译文”入口）。
- 增加“已校对”状态；AI 译文不应悄悄成为练习的参照。
- 翻译 provider 先复用现有 AI 配置，不新增一套设置；以后需要再拆“翻译模型”。

**验收**

- 粘贴一篇日文文章 → 翻译 → 中文出现 → 编辑 → 刷新后保留。
- 取消/失败/重试都有明确状态。
- 免费端点只适合试用；批量翻译建议用户自己的 Key。

---

### P1-2. 粘贴文本导入

**为什么先做这个**

- 公众号、网页、PDF、甚至手写句子，只要能复制就能进来。
- 不依赖任何站点规则，没有反爬、SSRF、新依赖。
- 抓取失败时用户不会卡死，粘贴永远可用。

**范围**

- 书架/首页提供“粘贴文本”：标题 + 正文。
- 自动分段、分句；识别是否已有相邻双语。
- 没有双语时作为单语章节导入，中文为空。
- 先按“一次粘贴 = 一章”处理；按标题自动分章以后再说。
- 保留现有 EPUB 导入和沉浸式翻译格式解析。

**验收**

- 粘贴公众号正文 → 生成一本书/一章 → 可读。
- 已有双语的文本能识别成 pair。
- 单语文本能正常阅读并触发翻译。

---

### P1-3. 书桌首页 + 空状态试读样例

**结构**

1. **继续阅读**（最重要）
   - 当前书/最近读的书、章节、进度、上次读到的句子。
   - 一个“继续”按钮直接进阅读器。
   - 没有书时变成“添加第一份材料”。

2. **添加材料**
   - 上传 EPUB / 粘贴文本（以后加链接）。
   - 首页的主要动作是“开始读”，不是“看介绍”。

3. **最近 / 全部书籍**
   - 保留现有卡片网格、搜索、排序、重命名、删除。
   - 默认显示最近几本，可展开全部。

4. **可选轻量信息**
   - 本数、句数、练习数，或“上次读到的一句话”。
   - 不做“今日一句/连续打卡”这种强练习感的东西。

**布局调整**

- 现在左侧 rail 列了一遍书名，主区网格又列了一遍；重构时去掉重复的 rail，导航让给“首页/书架/设置”或直接不要常驻导航。

**空状态 / 第一次打开**

- 做成真正的展示页：一句双语样例、这个工具是干什么的、两个入口（导入 EPUB / 粘贴文本）。
- 提供“试读这一篇”：读两句 → 选一句 → 回译 → 看反馈，不用导入就能体验核心。
- 把现有 WelcomeGuide 弹窗并进去，减少一层弹窗。

**验收**

- 有书时一次点击继续阅读。
- 新用户不导入也能试读样例。
- 桌面/平板/手机布局都正常。

---

### P1-4. 练习复盘

**现状**

- `AnalysisResult` 已经存了：分数、错误分类、优点、建议、用户译文、原文、时间。
- `practiceSlice` 还存了 notes / hints。
- 但没有页面能回看，关掉就散了。
- explain 的结果目前只在内存里（`useExplain` 的 state），刷新就没了。

**要做**

- 一个轻量的“练习记录”视图：
  - 按时间 / 书 / 错误类型筛选；
  - 显示原句、用户译文、分数、主要错误；
  - 点一条回到原句/练习桌，带着当时的译文和反馈；
  - 可选“再练一次”。
- 把 explain 的结果也落盘到句子上，复盘时能看到。
- 不做 SRS、闪卡、打卡、连续天数。

**验收**

- 练过的句子能在记录里找到。
- 筛选和跳转正常。
- 刷新后记录和讲解都还在。

### P2-1. 单篇 URL 导入 + 合集

**单篇 URL**

- 粘贴一个文章 URL，服务端抓取正文。
- 抓取失败时明确提示“直接粘贴正文”，不要卡死。
- 安全限制：只允许 http/https；阻止内网/私有地址；限制大小、超时、重定向。
- 微信公众号单篇 `mp.weixin.qq.com/s/...` 可以尝试，但不承诺稳定；专辑页不做。

**合集**

- “合集”就是一本特殊的书，章节 = 手动添加的文章。
- 支持一次粘贴多个链接/多段文本，逐篇加入。
- 不做刷新、未读、定时抓取、订阅。
- 天声人语这类材料：建一个合集，每天把文章加进去。

**验收**

- URL 成功/失败都有清晰结果。
- 合集能添加、删除、排序文章。
- 不依赖微信专辑页。

---

### P2-2. 全文搜索

- 书内搜索 + 跨书搜索。
- 先线性扫描，不上索引；材料量大了再优化。
- 结果能跳到原句。
- 支持日文和中文关键词。

---

### P2-3. PWA / 离线

- manifest + service worker + app shell 缓存。
- 离线打开已下载的书；AI/TTS 仍然需要网络。
- 更新策略要明确，避免旧缓存卡住。
- 手机端可安装。

---

### P3. 以后再做（signature）

- **自动注音**：网页文章没有 ruby，学习者需要；要分词 + 读音词典，评估包体积。
- **词典**：选中词直接看读音/释义，比每次调 AI 更快更便宜。
- **縦書き**：很有辨识度，但和现在的横向分栏分页是两套排版，工程大。
- **精选来源**：内置几个适合日语学习的来源，一键导入；不是 RSS。
- **浏览器扩展/分享入口**：只在真的需要时做。

---

## 4. 不做 / 反目标

- RSS/Atom 订阅、刷新、未读、定时抓取。
- 微信公众号专辑抓取、依赖第三方 RSS 桥。
- 账号体系、共享 API 额度、社区、共享译文库。
- 整本自动翻译。
- SRS、闪卡、打卡、连续天数、强制刷题。
- 云同步（先做手动导出/导入）。
- 每次打开都要经过的营销首页。
- 为“可能会有很多人用”提前做复杂架构。

---

## 5. 约束与风险

- **localStorage**：约 5MB；封面 data URL 和译文都很占空间；当前失败是静默的。
- **AI 成本/速度**：批量翻译消耗大；免费端点只适合试用；建议用户自己的 Key。
- **翻译质量**：机器译文是草稿，不是权威参照；必须可编辑、可校对。
- **对齐**：批量翻译可能数量不匹配；必须校验、重试、降级。
- **版权**：个人学习导入是一回事；公开站点不要托管/共享别人的译文或整本书。
- **URL 抓取**：SSRF、反爬、微信页面不稳定；必须限制并允许回退到粘贴。
- **pair ID 迁移**：会碰持久化数据；需要版本化 migrate 和测试。
- **公开但低流量**：不做账号/配额系统；服务端保持简单。

## 8. Goal 草案（一个 goal，内部 milestone）

> 一个 goal、一次执行。下面的 M0–M4 是内部顺序和自检点，不是多个 goal；不需要你分次确认。

**一句话版**

修数据底座 → 粘贴/文件/URL 输入 + 按章翻译 → 书桌首页 + 练习复盘 → 搜索/PWA/注音/词典/縦書き；一个 goal 跑完，核心优先，不停下等确认。

**Goal**

把 baku-yomi 补成“材料 → 双语 → 阅读 → 练习 → 复盘”的完整闭环：修掉多书串数据和存储静默丢数据的问题，支持多种材料输入，站内按章翻译并可校对，首页能继续阅读/添加材料，练习结果可以回看，并补上搜索、离线、注音、词典和縦書き等阅读能力。

**范围（同一个 goal 内按顺序完成）**

**M0 · 数据底座（必须）**
- pair ID 全局唯一 + 旧数据迁移（书籍、practice、bookmark）。
- 存储配额提示 + JSON 导出/导入；写入失败可见，不静默。
- 迁移测试：两本书同章节/同句序号互不影响。

**M1 · 输入与翻译（必须）**
- 粘贴文本导入；TXT/Markdown 文件导入；保留 EPUB 和沉浸式翻译格式。
- 按章 AI 翻译：批量、上下文、JSON 对齐校验、进度、取消、重试、增量保存、翻译缓存。
- 逐句编辑/重译；AI 译文/已校对标记；翻译 provider 先复用现有配置。
- 翻译后的中文能被练习桌当作参照。

**M2 · 首页与复盘（必须）**
- 书桌首页：继续阅读、添加材料、最近/全部书籍、搜索/排序。
- 空状态展示 + 内置试读样例；WelcomeGuide 并入，减少弹窗。
- 练习复盘：按时间/书/错误类型筛选；点回原句/练习桌；可选再练。
- explain 结果落盘，复盘可看。
- 不做 SRS/打卡/连续天数。

**M3 · 材料扩展（核心全绿后继续）**
- 单篇 URL 导入：服务端抓正文，失败回退粘贴；SSRF/大小/超时限制。
- 合集：一本书的章节 = 手动添加的文章；支持批量粘贴链接/文本；不做刷新/未读/订阅。
- 全文搜索：书内 + 跨书；先线性扫描；结果跳到原句。
- 书内目录/章节进度/“下一章”收尾。

**M4 · 打磨与辨识度（stretch）**
- PWA/离线：manifest、service worker、app shell 缓存；可安装。
- 自动注音：为无 ruby 的导入文本生成读音；评估词典体积，必要时懒加载/服务端。
- 词典：选中词看读音/释义，优先本地/轻量方案。
- 縦書き：作为可选阅读模式；如果和现有横向分页冲突太大，先做实验分支或停在设计验证。
- 阅读设置：字体、行距、页宽、主题；移动端滑动翻页。
- 精选材料源（不是 RSS）；浏览器扩展/分享入口只在确实需要时做。

**不做（这个 goal 之外）**

RSS/订阅、微信专辑抓取、账号/共享额度、社区/共享译文库、整本自动翻译、SRS/打卡/刷题、云同步、为规模提前做复杂架构。

**执行规则**

- 一个 goal 一次跑完，不在 milestone 之间停下来等确认。
- 每个 milestone 先通过自己的验收，再进入下一个。
- 同一个问题修两次仍失败就停下来报告，不要继续堆修复。
- M0–M2 是核心；M3–M4 在核心全绿后继续。M4 是 stretch：如果风险/时间明显变大，优先保证 M0–M3 正确，M4 可以停在“已开始/未完成”并如实报告。
- 每完成一个 milestone，在对话里留一条简短证据（命令输出 / 浏览器检查）。
- 全部完成后统一报告：改了什么、怎么验证、还有什么没做。

**保护现有功能**

- 不破坏 Bilibili 免 Key provider、explain、TTS、书签、主题、双栏分页、移动端选中。
- 保持现有 UI 方向：paper/night、binder workbench、桌面双栏跨页；除非新功能需要，不做大改版。
- 新依赖选最小可用；URL 抓取、分词/词典、PWA 都要说明体积和替代方案。
- 版权：不托管/共享别人的译文或整本书；个人学习导入是用户自己的责任。
- 公开但低流量：不加账号/配额系统；服务端保持简单。

**验收**

- `tsc`、`pnpm test`、`pnpm build` 通过；lint 不新增错误。
- 两本书同章节/同句序号，编辑、练习、复盘互不影响。
- 粘贴文章 → 翻译 → 编辑 → 练习 → 复盘可走通。
- 刷新后书籍、译文、练习、讲解都在；导出/导入可恢复。
- URL 导入成功/失败都有清晰回退；合集可添加/删除文章。
- 搜索能跳到原句；PWA 可安装/离线打开（如果 M4 做到）。
- 2022×954 / 1100×800 / 744×1134 / 390×844 宽度检查。
- 不 commit / push，除非明确要求。
