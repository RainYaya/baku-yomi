---

## 1. Combined verdict

**The workbench bones are specific; the shell is not.** The paired Japanese/Chinese sentence card, the recall-oriented practice panel, and the anchored-unit explanation panel are genuinely authored for this product. The weather/technical skin is mostly decoration: six themes, canvas overlays, and monospace body type do not change reading pace, progress, practice, or comprehension.

The bigger problem is interaction policy, not palette: **every selection opens a panel, and two panels compete with the text.** Reading is the primary act, but the app treats it as a side effect of practice.

**Design Health Score: 21/40 — Acceptable, significant improvements needed.**
**Technical audit: 11/20 — Acceptable.**

## 4. Priority issues

### P1 — Selecting a sentence is the same action as opening the practice panel

Clicking a sentence or pressing `j/k` opens the 360 px practice panel and reflows the reading column. There is no reading-only selection mode. After scrolling to the bottom and pressing `j`, the selected card was at `y=-545` while the panel showed only `译文` — the app had selected a sentence the user could not see.

**Why it matters:** The product is reading-first; back-translation is occasional. Every navigation step interrupts reading and can cancel the smooth scroll. The workbench feels attached to the reader rather than available when wanted.

**Fix direction:** Decouple selection from panel opening. Click/`j/k` selects and highlights; opening practice is a deliberate second action (`P`, a visible chip, or the card's own affordance). Keep the panel closed during `j/k`; remember whether it was open; fix the scroll race.

### P1 — The practice panel loses the sentence it is practicing

The panel hides `原文` until analysis, but the same Japanese sentence remains fully visible in the reader beside it. When the reader is scrolled, the panel shows only `译文`, `回译辅助`, and `你的回译` with no source context. The recall-first premise is contradicted by the reader, and the panel does not identify its sentence.

**Why it matters:** The learner cannot tell what they are practicing. If the selected card is offscreen, the panel is a floating form with no subject. If the Japanese is visible, recall is not enforced. The core loop is incoherent.

**Fix direction:** Pin a compact source line (or the selected fragment) at the top of the panel. If recall is the goal, blur it behind a `显示原文` toggle, or dim the selected sentence in the reader while composing. Do not rely on the reader for context. Make `优化译文` a suggestion with accept/revert, not an immediate overwrite.

### P1 — The explain panel is a dead end

No Escape handler. The header shows only the action label (`读懂` / `拆句` / `用法` / `语感`), not the selected fragment. Source sentence and units appear only after the answer. The streaming state can be empty for 12+ s; there is no timeout. At ≤1700 px it silently hides the practice panel, so opening `讲解` makes `练习` disappear without a mode switch.

**Why it matters:** The user loses the context they just selected, the panel looks broken when the model hangs, and the only exit is a small X. Practice context is erased without explanation.

**Fix direction:** Add Escape. Show the selected fragment and sentence immediately. Add `正在生成讲解…`, a request timeout, and cancel. Unify practice and explain into one surface with a segmented `练习 / 讲解` switch, or make explain an overlay, so one panel cannot silently erase the other.

### P1 — Error states are inconsistent and sometimes invisible

Auto-read failure calls `console.error` and returns to `off`; the user sees nothing. Voice speaker list prints raw `{"error":"fetch failed"}` with no retry. Explain and analysis streams have no timeout; explain stayed in `streaming` with an empty body for 12 s, practice stayed in `analyzing` with only a spinner after 4 s. `/api/analyze` took 97 s with no client abort.

**Why it matters:** The user cannot tell whether the app is slow, broken, or misconfigured, and no recovery path is offered. This is especially damaging for the keyless AI path, the default first-run experience.

**Fix direction:** Shared inline error/status component with plain language and retry. Auto-read: `朗读服务未连接` + link to voice settings. Voice list: `VOICEVOX 服务未启动` + retry. Request timeouts and cancel for explain/analysis.

### P2 — Accessibility and settings IA

- Import is a `<label>` wrapping a `display:none` file input with `tabIndex=-1`; keyboard users cannot import.
- Settings drawer has no `role="dialog"` / `aria-modal`, no focus trap, no initial focus; Tab reaches controls behind it.
- Theme dots are 10×10 px with no `aria-label`, only `title`; six dots, 18 px apart.
- Sidebar delete is focusable but `opacity: 0` until hover and deletes without confirmation.
- Snow-theme contrast: muted text 3.51:1, primary button text 2.97:1, Chinese translation ≈3.96:1 — below WCAG AA for normal text.
- Settings exposes only AI and voice; reading preferences (`showFurigana`, font zoom, layout) are missing; `blindMode`, `keywordMode`, `layoutMode` are dead settings.

**Fix direction:** Real buttons for import; focus trap + dialog semantics; `aria-label`s and larger theme targets; confirm destructive deletes; raise contrast; add a `阅读` tab (font, furigana, line width, theme, layout) and move cache/prefetch under `Advanced`.

### P2 — Touch targets and motion

- 25 icon-only buttons below 44×44; 8 below 24×24 (six 10 px theme dots, 21.5 px regenerate, 23.5 px close).
- No `prefers-reduced-motion` rules. With reduced motion emulated, three infinite CSS animations still run, and the snow canvas still animates.

**Fix direction:** Enlarge targets to at least 24×24 (preferably 44×44); add reduced-motion rules that stop canvas loops and CSS animations.

### P3 — Consistency and copy

- Two markdown renderers (`【】`/`####` vs `#`/lists/code) make the same model output look different in practice vs explain.
- Duplicate context: header repeats book title, sidebar repeats it, progress appears in topbar and as a 2 px bottom bar.
- Developer copy in the user UI: welcome guide footer tells the user to edit `docs/welcome-guide.md`; uploader describes itself as “一个偏工具站、偏安静的阅读界面”.
- Native `window.confirm` for book deletion; sidebar delete has no confirmation.
- Analysis score is a single number with five dots and no legend.
- `A-/A+` changes only the reader font, not the UI, and the zoom level is not displayed.
- Floating play/bookmark buttons are icon-only with `title` tooltips.

## 5. What is working

1. **Sentence-pair composition.** Japanese primary at 17 px/1.9; Chinese subordinate at 0.9em/0.65 with a faint left rule; selected state is a quiet accent wash plus a 2 px left bar. This hierarchy is specific to bilingual reading.
2. **Anchored explanation.** `SentenceUnitText` chips expose role/POS/meaning on hover/focus; the panel tells the reader when the unit table could not be aligned; the model-provenance note is the right reassurance.
3. **Keyboard foundation.** One priority dispatcher, `j/k` with scrolloff, `gi`, `?`, `Ctrl+Enter`, explicit state machines. The machine boundaries are clean.

## 6. How the new direction answers the audit

The approved UI v2 keeps the reading-first bones and changes the interaction policy:

- **Selection only highlights.** `j/k` never opens practice. Reading is a real mode.
- **Two practice levels, both kept.**
  - **S1 · 句内随手练:** `P` expands a practice card under the selected sentence, inside the reading column. The source is pinned in the card; the reading context stays visible. No right rail.
  - **S2 · 整页专注练:** the card's `练习桌 ↗` opens a full-page desk: source sheet left, writing sheet center, AI feedback right. `Esc` returns to the inline card, then to reading. Same sentence, draft, and feedback carry across.
- **Explain is a sibling tab in the same surface**, with the selected fragment pinned, Escape, timeout/cancel, and no ability to hide practice.
- **Two visual worlds:** paper/looseleaf light and night-reading dark are themes of the same structure, not competing structures.

This directly addresses P1 #1 (selection/panel coupling), P1 #2 (lost source), and P1 #3 (dead-end explain). P1 #4 (error states) and the P2 accessibility work remain implementation requirements, not design questions.

## 7. Open questions for implementation

1. What exactly persists when moving S1 → S2 → reading? Draft, feedback, scroll position, and which sentence was last practiced should all survive.
2. Does `Esc` from S2 always return to S1, or directly to reading when S2 was entered from a global mode switch? The recommended model is S2 → S1 → reading.
3. Should explain be a tab in the S1 card and a tab in the S2 desk, or a third sheet on the desk? The recommended model is a tab in both, sharing the same request state.
4. Does the practice desk support a queue of sentences, or only the current sentence? The current direction is one sentence at a time; a queue becomes a drill mode, which was rejected.
5. Which reading preferences belong in the new settings: theme (paper/night/system), font size, line width, furigana, reduced motion, and practice defaults.
